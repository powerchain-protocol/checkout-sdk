# Code of Conduct

**PowerChain Checkout™ UI SDK**  
**Enterprise Foundation Edition**  
**Version:** 1.0.0-beta.0

---

## Our Commitment

PowerChain™ is committed to providing a welcoming, professional, inclusive, and collaborative environment for everyone participating in our community.

We believe that open collaboration, technical excellence, transparency, and mutual respect are fundamental to building enterprise-grade software.

We welcome contributions from developers, designers, security researchers, enterprise partners, students, maintainers, and community members regardless of:

- Age
- Disability
- Ethnicity
- Gender identity
- Gender expression
- Nationality
- Race
- Religion
- Sexual orientation
- Technical experience
- Education
- Geographic location

Everyone is expected to contribute constructively and respectfully.

---

# Our Values

PowerChain development is guided by five core principles.

## Professionalism

We communicate respectfully.

Technical disagreements are expected.

Personal attacks are never acceptable.

---

## Collaboration

We value:

- constructive feedback
- code reviews
- documentation improvements
- architecture discussions
- knowledge sharing
- mentorship

Good ideas can come from anyone.

---

## Integrity

Be honest.

Report issues responsibly.

Credit the work of others.

Never intentionally misrepresent code, benchmarks, performance, or security.

---

## Quality

Enterprise software requires:

- maintainability
- readability
- documentation
- testing
- security
- reliability

Quality always comes before speed.

---

## Security First

Security is everyone's responsibility.

Contributors should:

- protect user data
- follow secure coding practices
- disclose vulnerabilities responsibly
- never publish sensitive information

---

# Expected Behaviour

Examples of behaviour that contributes to a positive environment include:

- Being respectful
- Being patient
- Accepting constructive criticism
- Helping new contributors
- Using inclusive language
- Writing clear documentation
- Following project standards
- Respecting review decisions
- Focusing discussions on technical topics
- Supporting collaboration

---

# Unacceptable Behaviour

The following behaviour is unacceptable.

## Harassment

Including but not limited to:

- insults
- threats
- intimidation
- discrimination
- stalking
- offensive comments
- abusive language

---

## Personal Attacks

Disagree with ideas.

Never attack individuals.

---

## Disruptive Behaviour

Including:

- trolling
- repeated off-topic discussions
- spam
- intentionally derailing conversations
- repeated low-quality submissions

---

## Security Abuse

Never:

- publish secrets
- expose API keys
- leak credentials
- disclose customer information
- exploit vulnerabilities without permission

Responsible disclosure is required.

---

## Intellectual Property Violations

Do not:

- submit copyrighted code without permission
- plagiarise documentation
- redistribute proprietary assets
- violate software licences

---

# Community Standards

Contributors should strive to:

- Write maintainable code
- Document public APIs
- Add tests where appropriate
- Follow repository conventions
- Keep pull requests focused
- Review respectfully
- Explain architectural decisions
- Help improve documentation

---

# Communication Guidelines

We encourage:

- respectful technical discussions
- evidence-based decisions
- reproducible bug reports
- thoughtful design proposals
- constructive code reviews

Avoid:

- inflammatory language
- sarcasm directed at contributors
- dismissive comments
- unnecessary arguments

---

# Code Review Expectations

Reviews should focus on:

- correctness
- architecture
- security
- maintainability
- documentation
- testing
- performance
- accessibility

Reviews should never become personal.

---

# Reporting Issues

If you experience unacceptable behaviour, please report it privately.

Include:

- description
- date
- evidence
- repository
- users involved

Reports will be handled confidentially whenever possible.

---

# Enforcement Responsibilities

Project maintainers are responsible for:

- enforcing this Code of Conduct
- investigating reports
- communicating outcomes
- protecting contributors
- maintaining a healthy community

Maintainers may remove, edit, or reject contributions that violate this policy.

---

# Enforcement Guidelines

Possible actions include:

## 1. Warning

Private communication explaining the violation.

---

## 2. Temporary Restrictions

Including:

- temporary comment restrictions
- review restrictions
- contribution restrictions

---

## 3. Suspension

Temporary suspension from contributing.

---

## 4. Permanent Ban

Repeated or severe violations may result in permanent removal from the community.

---

# Security Reporting

Security vulnerabilities should **not** be reported through public GitHub issues.

Please follow the responsible disclosure process described in:

- `SECURITY.md`

Do not publicly disclose security issues before they have been investigated and resolved.

---

# Scope

This Code of Conduct applies to:

- GitHub repositories
- Pull requests
- Issues
- Discussions
- Documentation
- Community forums
- Chat platforms
- Project events
- Official communications

It also applies when representing the PowerChain project in public.

---

# Open Source Philosophy

PowerChain encourages:

- open collaboration
- responsible innovation
- secure software
- enterprise engineering
- transparent governance
- long-term maintainability

We believe successful open-source communities are built on trust, respect, and technical excellence.
